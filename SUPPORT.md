# Soporte

Antes de solicitar soporte, revisa la documentación del proyecto y las issues existentes.

## Problemas técnicos

Utiliza GitHub Issues cuando tengas un problema reproducible relacionado con el funcionamiento del proyecto.

Incluye la mayor cantidad de información posible, como:

- Sistema operativo.
- Compilador.
- Versión de CMake.
- Configuración utilizada.
- Mensajes de error.
- Logs.
- Pasos para reproducir el problema.

## Preguntas

Las preguntas generales pueden realizarse mediante GitHub Discussions cuando el repositorio correspondiente tenga habilitada esta funcionalidad.

Evita utilizar issues para preguntas que no correspondan a un error o solicitud concreta.

## Solicitudes de funcionalidades

Utiliza el formulario de solicitud de funcionalidades para proponer nuevas características o mejoras.

Describe claramente el problema que intentas solucionar y el comportamiento que esperas.

## Seguridad

Las vulnerabilidades de seguridad no deben publicarse mediante issues públicos.

Consulta `SECURITY.md`.

## Código existente

Antes de solicitar ayuda con una parte específica del motor, revisa primero la documentación y el código correspondiente. Proporcionar un ejemplo mínimo reproducible facilita considerablemente el diagnóstico.
