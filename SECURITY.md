# Política de Seguridad

## Reportar una vulnerabilidad

Las vulnerabilidades de seguridad no deben publicarse en issues públicos.

Si encuentras una vulnerabilidad relacionada con FunshiEngine, comunícala de forma privada a los mantenedores.

El reporte debería incluir, cuando sea posible:

- Descripción de la vulnerabilidad.
- Pasos para reproducirla.
- Versiones o commits afectados.
- Posible impacto.
- Ejemplo o prueba de concepto, si existe.
- Cualquier otra información útil para investigar el problema.

## No publicar información sensible

No publiques públicamente:

- Exploits funcionales.
- Credenciales.
- Claves privadas.
- Información personal.
- Detalles técnicos que puedan facilitar la explotación de una vulnerabilidad antes de que pueda ser corregida.

## Proceso de investigación

Los mantenedores analizarán el reporte y determinarán:

1. Si el problema constituye una vulnerabilidad.
2. Qué versiones o componentes están afectados.
3. La gravedad del problema.
4. Las medidas necesarias para corregirlo.

## Divulgación

Los detalles técnicos de una vulnerabilidad deberían divulgarse públicamente después de que los mantenedores hayan tenido la oportunidad razonable de investigarla y corregirla.

La divulgación coordinada permite reducir el riesgo para los usuarios del proyecto.
